This guide is for adding content to the Grit documentation. It is not meant for user consumption.

Our docs are written in [MDX](https://mdxjs.com). The custom components below are imported from `~/components`, and the [Starlight components](https://starlight.astro.build/components/using-components/) are also available.

## Terminology

1. Always refer to metavariables as `metavariables`, not `meta-variables` or `variables`.
2. Patterns accept `arguments`, not `parameters` or `variables`.

## Tips

1. Use `## Header \{#custom-id\}` to add a custom id anchor to a header (the braces are escaped because MDX reads `{…}` as an expression). This is useful for linking to a specific section.

## Asides

Use [Starlight's asides](https://starlight.astro.build/guides/authoring-content/#asides) to show an important detail.

## Custom components

### `<Gate>`

`<Gate>` can be used to hide content behind a feature flag.

<Gate flag="LANG_CSS">
This content is hidden behind the `foo` feature flag.
</Gate>

### `<Collapse>`

Collapses are used to hide large blocks of text.

<Collapse title="Show details">
This is hidden.

`className` is a prop that can be passed to the collapse tag.
`boxed` is a boolean prop.
</Collapse>

<Collapse title="Boxed collapse" boxed>
This is a boxed collapse.
</Collapse>

### `<DiffEditor>`

Diff editors are used to show the effect of applying a pattern to a piece of code.

<DiffEditor>

```grit
`foo($x)` => `bar($x)` // the pattern, displayed first
```

```javascript
`foo(1)`; // the code before, displayed bottom left
```

```javascript
`bar(1)`; // the code before, displayed bottom right
```

</DiffEditor>

### `<MatchEditor>`

Match editor is used to show pattern and the output with code highlight.

<MatchEditor>

```grit
// A pattern you want to showcase highlighting for. (This is eg. only)
`foo($x)` => `bar($x)`
```

```javascript
// Highlights that span a few characters.
const {hl}foo{/hl} = bar.{hl}getVal{/hl}(1);

// Highlights that span multiple lines.
const match = {hl}{
  name: 'tag',
  values: [1, 2, 3]
}{/hl};
```

</MatchEditor>

### `<Snippet>`

Snippets show a pattern with a "Run Pattern" link that opens it in the playground, running against the sample code passed as `input`. Sample files live in `src/partials/` and are imported as strings:

````mdx
import tutorialSnippet from '~/partials/tutorial_snippet.js?raw';

<Snippet input={tutorialSnippet}>

```grit
`console.log($message)`
```

</Snippet>
````
